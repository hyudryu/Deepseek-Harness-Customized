# Agent Note: 按需 skill 目录分组

Status: implemented

[English](2026-09-07-skill-catalog-buckets.md) | 中文

## Problem

即使任务只需要一个主题，所有已安装 skill 名称和描述组成的完整目录仍会消耗模型输入。大量 skill 可能占据首次请求的大部分内容，并在压缩之前保留于后续每次请求中。按需加载指令正文无法限制这部分初始发现成本。

## Decision

[skill 目录分组](../../../../packages/skill/skill-catalog-buckets/README.zh.md) 通过 [tool-skill](../../../../packages/skill/tool-skill/README.zh.md) 中作用域内的 `skill/catalog` 呈现扩展发布简短的类别描述和数量。`skill_catalog` 工具返回指定类别的一页有界摘要，并可按查询词筛选。现有 `skill` 工具加载完整指令，显式 `/name` 调用仍独立于类别发现。

Web 组合包启用此呈现。其他组合通过挂载插件显式启用。可配置的有序关键词规则将每个模型可调用 skill 分配给首个匹配类别，未匹配项归入 `other`。这一机制只对提供方元数据分组，不移动文件，也不需要 AWS 存储；AWS 类别表示一个主题。

目录发布方保留仅追加的会话历史，通过现有生命周期发布替换的发现文本。已保存的完整目录仍属于历史输入，直到新会话或正常压缩使其不再进入当前请求。启用插件绝不删除或改写会话日志、提供方文件或先前的工具结果。

## Alternatives considered

- 缩短每条描述仍使输入成本与全部已安装 skill 成正比，而且可能删去选择 skill 所需的线索。
- 通过模型或远程分类器选择 skill 会增加延迟、凭据需求和不确定的发现结果。有序本地规则使分类可配置且可重复，代价是匹配可能不准确。
- 改写已保存的目录可以立即减少恢复会话的上下文，但会改变持久历史及其回放语义。

## Consequences

初始发现成本随配置的类别数增长，而非随已安装 skill 数增长。agent 需要额外一次工具调用来取得摘要，并可在加载指令前搜索某个类别。过于宽泛的关键词可能错误分类 skill；用户可以调整有序规则或查看 `other`。可用性仍由提供方和调用权限决定，已加载的指令正文仍无大小上限。

针对提供方和真实 Loader 的测试覆盖分页、筛选、可见性、替换目录和不变的正文加载。无需密钥的记录会话快照验证实际进入模型输入的类别消息和分页结果。
