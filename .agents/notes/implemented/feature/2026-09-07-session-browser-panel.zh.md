# Agent Note: 会话浏览器面板

Status: implemented

[English](2026-09-07-session-browser-panel.md) | 中文

## 问题

浏览器操作需要可见的页面状态，让用户跟踪导航并检查失败。消息输入区旁边的控件会掩盖它与应用侧面板的关系。服务器成功启动本身不能证明浏览器创建、Remote 传输和客户端渲染能够协同工作。

## 决定

[布局](../../../../packages/client/ui-layout/README.zh.md) 拥有右上角的 `browser.toggle` 槽位和会话级浏览器栏。[浏览器 UI](../../../../packages/client/ui-browser/README.zh.md) 检查 Remote 结果并显示操作失败。面板可见性与浏览器上下文生命周期相互独立：隐藏面板后，浏览器仍可供智能体操作。

[控制器](../../../../packages/api/browser-controller/README.zh.md) 先订阅再读取初始快照，并等待上下文关闭后才确认关闭。browser-control 提供方通过 Playwright 上下文的 close 事件跟踪关闭状态，并在调用方之间共享正在进行的上下文创建。同一上下文提供快照画面和操作历史。

可选 browser-control bundle 一起挂载提供方、控制器和 UI。打开操作要求存活的 Session；流只保留最新的待发送替换快照。框架绑定的可观察数据源在浏览器关闭和重开期间管理客户端订阅。上下文关闭失败会向调用方传播，并保留可重试的提供方状态。截图光标坐标考虑留白，每个调整手柄跟随其自身面板边缘。

首次导航失败时会发布已打开的上下文，以便面板停止浏览器。未安装可选提供方时，默认 Web 配置不显示浏览器控件；内部展示组件不对外公开。

## 考虑过的替代方案

**保留输入区控件。** 浏览器属于应用查看状态，因此其切换按钮应与面板控件放在一起，而非消息输入区。

**将服务器启动视为浏览器验证。** 启动无法揭示 Playwright 方法不匹配或客户端模块缺失。验证包括真实 Chromium 导航，以及 Web 客户端中的可见页面画面。

## 后果

用户可以在隐藏面板时保持会话浏览器运行。显示的画面是截图，不是交互式远程桌面；在其上移动指针不会发送浏览器输入。测试覆盖共享创建、画面传输和关闭后重新打开，浏览器验证则覆盖组合后的应用。
