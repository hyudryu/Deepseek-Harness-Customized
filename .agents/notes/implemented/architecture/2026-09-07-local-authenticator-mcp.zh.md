# Agent Note：本地身份验证器账户与 MCP 工具

Status: implemented

[English](2026-09-07-local-authenticator-mcp.md) | 中文

## 问题

会话需要获取用户导入的身份验证器账户的当前验证码，设置配置卡片需要导入和删除账户。配置密钥不能成为设置值或工具输出。

## 决策

[身份验证器插件](../../../../packages/host/authenticator/README.zh.md) 拥有一个由设置、原生会话工具和经过身份验证的 MCP 端点共享的本地账户文档。二维码图片在浏览器中解码，只有标准 TOTP URI 通过现有应用身份验证连接传输。响应仅返回账户身份和当前验证码，不包含配置密钥。导入和删除属于管理操作，原生及 MCP 工具只发现账户并请求当前验证码。

## 理由

复用应用 cookie 和来源检查，使移动端和桌面端使用相同的身份验证机制。另行启动未经身份验证的 MCP 进程会在该机制之外暴露验证码，并增加一个启动入口。官方 MCP SDK 在 Web 服务器上实现无状态 Streamable HTTP；持续维护的 OTPAuth 库负责解析标准配置 URI 并生成 TOTP。

密钥应保存在独立的本地文档中，而不是值会投射到配置客户端的设置命名空间。原子替换和跨进程写锁防止文件不完整以及并发导入丢失。Windows ACL 或 POSIX 仅所有者权限限制其他操作系统账户访问，但不隔离同一用户运行的代理，也不加密存储。

## 考虑过的替代方案

将配置密钥存储在共享设置文档中会通过配置视图暴露密钥。启动独立的公共 MCP 进程则需要新的身份验证和应用启动机制。在现有经过身份验证的 Web 应用后使用同一个私密账户存储，可以避免这两项成本。

## 影响

导入账户允许每个已组合会话请求当前验证码。返回的验证码成为普通会话工具结果，可能发送给配置的模型服务商，但配置密钥不会发送。支持范围为六位 TOTP，因此 HOTP、迁移导出和其他位数均返回明确错误。

行为验证覆盖带前导零的 RFC 派生验证码、重启持久性、并发导入、重复拒绝、删除、私密数据投射及无效持久数据保护。真实 Loader 组合验证 cookie 与来源拒绝、管理路由、原生工具处理器和官方 MCP 列表与调用响应。面向模型的快照记录两个工具定义；浏览器验证负责图片上传与展开的设置卡片。
