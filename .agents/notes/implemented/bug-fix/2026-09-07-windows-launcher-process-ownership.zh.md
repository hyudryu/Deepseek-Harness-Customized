# Agent Note: Windows 启动器的进程所有权

Status: implemented

[English](2026-09-07-windows-launcher-process-ownership.md) | 中文

## 问题

TCP 监听器的 PID 不能证明 Windows 启动器拥有该进程。强制终止监听器可能破坏其他应用的状态，或绕过 dsh 的异步插件清理。存放在源码检出目录中的插件归档也会随该目录的删除而丢失。

## 决策

[RUN.bat](../../../../RUN.bat) 在端口 3080 被占用或监听器检查失败时，在安装或构建之前拒绝启动，且不会终止监听器。重启要求用户在现有 dsh 控制台按 Ctrl+C 并等待进程退出，使[配置启动信号处理器](../../../../apps/cli/src/profile-boot.ts) 能够等待清理完成。在安装之前检查也能避免重新构建现有实例使用的文件。

[RUN.md](../../../../RUN.md) 要求保留的插件归档位于检出目录之外的绝对路径。自定义 dsh 主目录也只有在满足该条件时才适用。

## 考虑过的替代方案

**终止端口所有者。** 端口号既不能证明所有权，也不能证明进程已准备好终止；强制终止还会跳过异步清理。

**自动优雅重启。** 启动器没有经过身份验证的停止端点或持久化进程身份记录。增加跨进程关闭协议属于独立的生命周期功能；手动关闭复用现有清理流程，无需从 PID 推断所有权。

## 影响

重启需要在现有控制台中明确停止进程。启动器无法修复遗留或挂起的进程，但能保留其他服务并避免强制跳过清理。可用性检查后仍可能出现监听器；应用启动流程仍负责处理绑定失败。

## 验证

[启动器测试](../../../../scripts/run-launcher.spec.ts) 覆盖端口占用时拒绝启动且保留独立拥有的监听器、没有监听器时预检成功，以及监听器枚举失败。端口占用回归测试会拒绝强制终止进程的启动器，独立并发测试验证资源隔离。插件模式验证仍由 [QA 插件回归测试](../../../../Custom%20Plugins/qa-testing/test/output-schema.test.mjs) 覆盖。
